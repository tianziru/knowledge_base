# 灵犀智库 · 技术架构

## 1. 架构总览

系统采用 **双进程 + 双 LangGraph + 共享基础设施** 的分层架构：

```
┌─────────────────────────────────────────────────────────────────┐
│  表现层                                                          │
│  import.html (:8000)          chat.html (:8001)                 │
│  导入后台 SPA                    问答前台 + SSE 进度               │
└───────────────┬─────────────────────────────┬───────────────────┘
                │                             │
┌───────────────▼─────────────┐ ┌─────────────▼───────────────────┐
│  接入层 FastAPI               │ │  接入层 FastAPI                  │
│  file_import_service :8000  │ │  query_service :8001           │
│  /upload /status /tasks …   │ │  /query /stream /history …      │
└───────────────┬─────────────┘ └─────────────┬───────────────────┘
                │ BackgroundTasks             │ BackgroundTasks
┌───────────────▼─────────────┐ ┌─────────────▼───────────────────┐
│  编排层 LangGraph             │ │  编排层 LangGraph                │
│  kb_import_app              │ │  query_app                     │
│  ImportGraphState           │ │  QueryGraphState                │
│  管道：解析→切分→向量→入库     │ │  确认→并行检索→融合→生成         │
└───────────────┬─────────────┘ └─────────────┬───────────────────┘
                │                             │
        ┌───────┴─────────────┬───────────────┴────────┐
        ▼                     ▼                        ▼
┌───────────────┐   ┌─────────────────┐   ┌────────────────────┐
│  模型层 lm/    │   │  存储与中间件     │   │  外部云服务          │
│  LLM / VL     │   │  Milvus         │   │  MinerU PDF 解析   │
│  BGE-M3       │   │  MinIO          │   │  DashScope / MCP   │
│  Reranker     │   │  MongoDB        │   │  Neo4j（预留未用）   │
│               │   │  SQLite / Redis │   │                    │
└───────────────┘   └─────────────────┘   └────────────────────┘
```

Redis 为可选中间件：配置 `REDIS_URL` 后承担任务权威存储与 SSE Pub/Sub，否则回退 SQLite + 本地队列。

**核心原则**：导入写、查询读；两图不互相 `invoke`，通过 **Milvus 中的 `item_name` + 切片** 间接衔接。

## 3. 运行时拓扑

| 进程 | 入口 | 端口 | 编译图 |
|------|------|------|--------|
| 导入服务 | `python -m app.import_process.api.file_import_service` | `127.0.0.1:8000` | `kb_import_app` |
| 查询服务 | `python -m app.query_process.api.query_service` | `127.0.0.1:8001` | `query_app` |

- 两服务 **独立进程**，无统一 API 网关，CORS 均为 `*`。
- 任务 / SSE 双后端：未配置或连不上 `REDIS_URL` 时（`REDIS_REQUIRED=0`，默认）走 **SQLite `data/tasks.db` + 进程内热缓存 + 本地 SSE 队列**，启动时将未结束任务标 `failed`。连接失败会在进程生命周期内固定为该回退，任务与 SSE 不再各自重试 Redis。连接成功则 Redis 为权威存储（Hash + ZSET + lease）与 Pub/Sub SSE；本机 dict 仅写缓冲，读写直达 Redis。`REDIS_REQUIRED=1` 且连接失败则启动失败。
- Redis 租约：本进程把任务写成 `pending`/`processing` 时写入 `owner`（`worker_id`）并 `SET …:lease EX TASK_LEASE_TTL_SEC`（默认 30s）。持有方约每 `TTL/3` 续这些任务的租约，进度写穿也会续期；只从 Redis 灌入的他机任务不续期。读路径（`get_task_status` / `list_tasks` / `get_task_stats`）懒检测，lease 不存在则标 `failed`（`error=任务租约过期（worker 可能已退出）`）。**禁止**启动时全局把进行中任务标 failed，以免误杀他机任务。
- 查询流式：`POST /query`（`is_stream=true`）+ `GET /stream/{session_id}`（SSE）。

## 4. 编排层：双 LangGraph

### 4.1 导入图 `kb_import_app`

**形态**：前条件分支 + 后线性管道。  
**调用**：`kb_import_app.stream(state)`。

```
node_entry
  ├─ PDF  → node_pdf_to_md ─┐
  └─ MD/Office→MD ──────────┴→ node_md_img
       → node_document_split
       → node_item_name_recognition   # 写 kb_item_names_v2
       → node_bge_embedding
       → node_import_milvus           # 写 kb_chunks_v2
       → END
```

| 技术点 | 说明 |
|--------|------|
| 状态 | `ImportGraphState`：`task_id`、路径开关、`md_content`、`chunks`、`item_name` |
| PDF | MinerU 云 API（申请 URL → 上传 → 轮询 → ZIP → MD）；页数超过 `MINERU_MAX_PAGES` 时节点内拆分、有限并行再合并 |
| Office | `office_to_md`：txt/docx/pptx → MD |
| 切分 | 标题切分 + RecursiveCharacter（>2000 再切，<500 同父合并） |
| 向量 | BGE-M3 dense(~1024) + sparse，文本前缀带商品名 |
| 幂等 | 同 `item_name` 入库前删除旧切片 / 旧商品名记录 |

### 4.2 查询图 `query_app`

**形态**：商品确认条件边 + 四路扇出汇合 + 融合生成。  
**调用**：`query_app.invoke(state)`。

```
node_item_name_confirm
  ├─ 已有 answer（反问）→ node_answer_output → END
  └─ 无 answer → node_multi_search
         ├→ node_search_embedding      # kb_chunks_v2，item_name 过滤
         ├→ node_search_embedding_hyde
         ├→ node_web_search_mcp
         └→ node_query_kg（空桩）
              → node_join → node_rrf → node_rerank → node_answer_output → END
```

| 技术点 | 说明 |
|--------|------|
| 状态 | `QueryGraphState`：多源 chunks、`rrf`/`rerank`、`answer`、`item_names` |
| 确认 | LLM 抽型号 → 查 `kb_item_names_v2` → 高分确认 / 中分反问 / 无匹配放行 |
| 融合 | RRF 多源合并 → 本地 BGE Reranker → LLM 生成 |
| 会话 | Mongo `chat_message`；流式经 `sse_utils` |

### 4.3 两图衔接（数据面，非图边）

```
导入识别 item_name ──► kb_item_names_v2 ◄── 查询 confirm
导入切片+向量     ──► kb_chunks_v2      ◄── 查询 embedding / HyDE
字段 item_name 贯穿两侧，避免串型号
```

## 5. 数据架构

| 存储 | 资源 | 用途 |
|------|------|------|
| Milvus | `kb_chunks_v2` | 文档切片：content、item_name、dense/sparse |
| Milvus | `kb_item_names_v2` | 标准商品/设备名 + 双向量 |
| MinIO | bucket（如 `knowledge-base-files`） | 原稿、MD 内图片公网 URL |
| MongoDB | `kb002.chat_message` | 多轮对话历史 |
| 本地磁盘 | `output/YYYYMMDD/<task_id>/` | 任务工作目录 |
| SQLite | `data/tasks.db` | 默认/回退：导入/查询任务状态与节点进度；进程内 `task_utils` 内存为热缓存 |
| Redis（可选） | `{prefix}:task:*` Hash、`{prefix}:tasks:index` ZSET、lease String+TTL、`{prefix}:sse:{session}` Pub/Sub | 配置 `REDIS_URL` 后的任务权威存储与跨实例 SSE；前缀默认 `kb` |
| Neo4j | 配置预留 | **业务未接入** |

检索栈：**BGE-M3 混合检索（WeightedRanker）→（多路）RRF → Rerank → LLM**。

## 8. 横切与工程约定

- **Prompt**：`load_prompt(name)` 读 `prompts/{name}.prompt`，`.format(**kwargs)` 渲染。
- **进度中文名**：`task_utils._NODE_NAME_TO_CN` 映射节点 ID → 前端日志文案。
- **限流**：图片 VL 等路径使用 `rate_limit_utils`。
- **安全现状**：无登录；上传做扩展名与 basename 防路径穿越；Milvus 过滤对 `item_name` 做转义。

## 9. 架构特点与已知边界

**特点**

1. 读写分离、图状态模型分离，适合不同 SLA。
2. `item_name` 作为业务主键，贯通导入幂等与查询过滤。
3. 查询侧多路检索 + 反问短路，兼顾精度与体验。

**边界 / 债务**

1. `node_query_kg` / Neo4j 为空实现。
2. 默认 SQLite + 热缓存，多 worker 不共享内存、需共用 `data/tasks.db` 并注意写锁。可选 Redis 后多实例共享任务与 SSE；孤儿任务靠 lease 懒回收，启动不批量 failed。不自动 SQLite↔Redis 迁库；Pub/Sub 无历史，进度可走 `/status` 轮询补偿。`answer` 等非 `error` 结果仍不落库。
3. 无网关与鉴权；密钥集中在 `.env`。
4. 导入部分切分开关（silicon/vllm 等）未接线。
